# Project decisions
- Keep product records, searchable model examples and example drawings in `src/data/products.ts`, category presentation in `src/pages/productsData.tsx` and media in checked-in asset pointers; label example geometry separately from range specifications. Share the catalogue pointer through siteConfig so all downloads serve the same edition.
- Define shared contact details, including WhatsApp, in `src/lib/siteConfig.ts` and import them wherever contact links render to prevent inconsistent destinations.
- Render privacy and terms routes through the shared LegalPage with existing page styles to keep legal placeholders consistent without redesigning the site.
- Store approved legal sections in `src/data/legal.ts`; empty arrays render a contact placeholder so legal copy is never fabricated.
- Use the shared NotFound page for unmatched application and catalogue routes so recovery links and page titles agree.
- Use the inherited `--focus-outline` token or `data-focus-surface` for dark focus contexts so CSS Modules share one focus-ring rule.
- Product pages follow the MAPAL reference information pattern — competence hero intro, featured example highlight, key capability blocks and product-family sections — with exactly four solution areas on the /products overview (Solid Carbide with End Mills/Reamers/Drills families, PCD Tools, Brazed Carbide Tools, Specialized Solutions); no all-products catalogue view exists, structure lives in src/pages/productsData.tsx.
- Use shared productNavigation for overview and navbar destinations; navbar families expand on click with aria-expanded and reset after navigation.
- Render unapproved capability or service claims through the shared ContentPending component instead of fabricating copy; pending blocks carry no invented body text. Flags show in development and in builds with `VITE_SHOW_PENDING=true` (`src/lib/contentPending.ts`); production builds hide them and leave out blocks whose only content is a pending flag.
- The About page renders no founders or leadership content; founder material is not required for this site.
- Share the industry options and icons through src/data/industries.ts across Home, Contact and catalogue filters; keep product industry assignments source-backed rather than inferred from company sectors.
- Use the shared PhotoPlaceholder for missing real photos so neutral icon panels replace stock imagery consistently.
- Keep equipment definitions in src/data/equipment.ts with page-specific summaries so Home, About and Technology share one inventory without changing their copy.
- Keep service block definitions in src/data/services.ts so the Home services section and the Technology & services page render the same approved copy and pending placeholders.
- Define category colours only in src/index.css and reference category tokens from shared catalog data and application pages so product technologies remain visually consistent.
- Use index.css and CSS Modules only; unused shadcn scaffolding is removed to keep the static site dependency surface minimal.
- Define responsive title, section, small-heading and body tokens in index.css; apply the semantic hierarchy above module typography and share tokens with non-semantic titles and the Home carousel to keep content consistent without resizing compact navigation controls.
- Share section-spacing and section-heading-gap tokens for regular content bands; preserve hero framing and readable article widths.
- Render journey milestones once in a responsive chronological list; use shared section-heading classes and semantic accent/rule tokens across content sections, excluding page, card and carousel titles, to keep the reference treatment consistent and themeable.

- Use BrowserRouter with real paths (no `/#/`). Every public route in `src/lib/publicRoutes.ts` is pre-rendered at build time (`src/entry-server.tsx` + `scripts/prerender.ts`) to `dist/<path>.html` with its own title, description, canonical URL and LocalBusiness JSON-LD, plus a noindex `404.html`; `main.tsx` hydrates only when the HTML matches the current path and rewrites legacy `/#/` links to real paths. Add new pages to `publicRoutes` so the sitemap and pre-render stay in step. Resolve category IDs and product slugs through the shared product route to preserve existing links.
- There is no side enquiry tab (removed on all screen sizes): the header top bar, the WhatsApp button (no pulse animation) and each page's own call to action carry enquiries. No quote buttons or add-to-quote selection exist.
- Render the shared catalogue download on Contact; redirect legacy /downloads links to /contact so existing bookmarks still reach the catalogue without a separate Downloads page.
- Preserve the quote context identity through Vite hot-update data so mounted providers and refreshed consumers cannot diverge during preview updates.
- Validate quote fields and attachments in src/lib/rfq.ts and call its single submitRfq boundary; future delivery connects here without changing the form.
- Route titles, descriptions, canonical and og:url come from `getRouteMeta` in `src/lib/routeMeta.ts`: written into each page's HTML at build and kept in step by RouteMeta/useDocumentMeta during navigation. The share image remains sitewide. Keep code that runs during render free of `window`/`document` so pages pre-render.
- Keep one focusable main landmark around route content and lazy-load all non-Home pages so navigation stays accessible and the initial bundle stays lean.
- Use the shared carousel playback hook so every timer respects reduced motion, focus, touch and explicit pause, and render its visible play/pause button (`data-carousel-toggle`, excluded from the focus/touch auto-pause). The Home hero starts paused (`autoplay: false`): nothing moves until the visitor presses Play.
- Use Poppins for headings and body text (Fontsource weights 400/600/700); font tokens `--font-heading` and `--font-body` live in index.css.
- Allow the resolved dependency directory in Vite's development file serving so symlinked Fontsource assets load in the preview.
- Keep news content in `src/data/news.ts` (supplied file, only `published` items render) with presentation helpers in `src/lib/news.ts`; regenerate `public/sitemap.xml` and `public/robots.txt` (with its `Sitemap:` line) with `bun scripts/sitemap.ts` from `siteConfig.siteUrl` so held articles never leak into routes or the sitemap.
- Generate `public/rss.xml` during both build modes from published news; share links use the configured public real-path article URL, and RSS omits unconfirmed publication dates so subscriptions never expose held posts or fabricated dates.

- Category photographs and verified matching product/news entries use optimized client-source asset pointers; preserve complete tool geometry and distinguish pictured examples from the broader range. Images render plainly with no zoom, lens or lightbox anywhere (removed at client request); Gallery offers thumbnail switching only.

- Use PageHero for secondary banners; product pages keep text-only intros. Solid Carbide families show approved photos and supplied copy, including optional extra paragraphs, from shared records. Preserve Home/Contact heroes. The Home h1 is visible in the hero, fixed above the rotating slide text; slide titles stay h2.

- Asset pointer URLs (`*.asset.json`) are made root-absolute by the plugin in `vite.config.ts`, so pages at any depth resolve them; use `pointer.url` directly and never prefix `import.meta.env.BASE_URL` (that produces a protocol-relative `//images/...`). The base path comes from the path part of `VITE_SITE_URL` (the GitHub Pages workflow sets `https://mouryaspragna.github.io/rmtt-spark-foundation`, so it builds for `/rmtt-spark-foundation/`); `VITE_BASE` overrides it. Never hard-code root paths such as `/images/...`; prefix `import.meta.env.BASE_URL` for files in `public/`.
- Security headers (CSP with `frame-ancestors 'none'`, Permissions-Policy, HSTS and others) are generated into `dist/_headers` by `scripts/headers.ts`; the CSP adds the `VITE_RFQ_ENDPOINT` origin automatically. When adding any third-party script, font, image or API, allow its origin there. Hosts that ignore `_headers` need the same values set in their config or a Cloudflare proxy in front.
- Home product range shows the four families as one row of four, 2×2 below 1100px, so no card sits alone.
- Scroll motion is site-wide and lives in `src/lib/scrollMotion.ts`, started once from AppShell after hydration: section headings, closing bands and a few single blocks fade up 16px over 600ms; the listed card grids reveal their children 90ms apart (four steps at most); lazy images fade in on load. Opt a new block in by adding its selector or grid class name there, never by per-page wiring. Content already on screen is never hidden, nothing is hidden in the pre-rendered HTML, and reduced motion turns it all off. All cards share one hover (2px lift, `--shadow-lg`, 180ms) mapped in `index.css`. Keep `npm run lint` at zero problems.
- Zod runs in jitless mode (`z.config({ jitless: true })` in `src/lib/rfq.ts`) because its compiled validators use `new Function`, which the CSP blocks.
- Visual system (website build standards): colours are the "Riddhi Steel" palette derived from the logo (slate #707E85, steel blue #B8CBD9 as `--logo-*` for rules and fills only; darker same-hue tokens for text and links); RMTT orange is the one accent, for section headings and buttons. Type uses the seven-step scale in `index.css` (`--text-xs` 12, `--text-sm` 14, `--text-md` 16, `--text-lg` 18, small heading 22, heading 32, title 60) — never hard-code font sizes in modules. Every content band uses `--section-spacing`; every radius is the 4px token except buttons, which are pills (`--radius-pill`); depth is hairline borders with one `--shadow-lg` for raised elements.
- Section headings: `.section-heading` shows its `.section-eyebrow` label, a sentence-case H2 in RMTT orange (`--section-heading-accent` #B95000; `--section-heading-accent-on-dark` #F0913A on dark bands) and an intro, left-aligned, with no rule; the label stays steel blue. Orange is for section heading text and buttons, never body text; it lays out as a row only when it has a direct link child. Dark bands set `data-surface="dark"`.
- Buttons: orange pills (`--btn-bg` #B95000, hover `--btn-bg-hover` #8F4A05, white text) — one filled primary, one orange-outlined secondary — plus a steel-blue text link with the lucide ArrowRight icon, mapped by module class name in `index.css`; never type "→" into button text. The current nav item is marked with an accent underline.
- Scroll-reveal styles apply only under `html.js` (set in `main.tsx`) and to elements tagged by scrollMotion, so pre-rendered content stays visible without JavaScript.
- Client studio group photos (grey backdrop) use the shared `StudioPhoto` band (`src/components/StudioPhoto.tsx`) with the `--studio-backdrop` gradient sampled from the photos, so they run edge to edge without a box; keep the band exactly as tall as the photo. Categories with `studio: true` (Solid Carbide) get a studio hero, family cards with photos (`cardImage`) and family pages laid out as banner, then story left and a specifications card right.
